01 The problem

两个答案，
不等于两次独立判断。

人工编码的分歧，常常只剩一个结果，没有留下通往结果的路径。模型能把路径写出来，但它写出来的自信，也可能只是自信。

01

人工编码的差异不可复现

同一份规则、同一篇论文，隔一周再编一遍，结果可能不同。两个编码员之间的分歧，往往只留下「最后选了哪个值」，没有留下可回查的推理路径。

02

单一模型的自信心不等于准确率

模型输出的 confidence 是自评，不是校准概率。一个语气笃定的错值，比一个空值更难被发现；两个模型都「高置信」，也可能只是共享了同一个误读。

分歧不是噪声。
它是核对开始的地方。 — 这套工具的前提
Method note

A / B 是独立进程，提示词逐字节一致，只共享同一份 packet。分歧至少不是提示词差异造成的；但共享输入的错误会被两者同时继承，所以一致样本仍需审计。

02 The pipeline

从一份文档，
到一份可核对的清单。

规则文档不是代码里的常量。它被解析成规则包，经人确认、锁定哈希，再驱动后面的每一步。换一份文档，就换一个课题。

Document → Pack → A ∥ B → Diff → Adjudicate → Revisions
  1. 01

    规则文档

    Input

    人写的编码规则，Markdown / PDF / DOCX 原样上传。不要求先改写成模板，也不把规则藏进代码。

    CODING_PLAN.md
  2. 02

    规则包

    G1 · 人工确认

    模型解析出字段表：名称、类型、取值域、缺失规则、原文出处。每字段必须有出处；确认后锁定 pack_hash。

    pack.json · fields.yaml
  3. 03

    双模型独立编码

    A ∥ B

    两个独立进程，提示词逐字节一致，结果分开落盘。先证明两边看到的是同一份输入。

    coder_a.jsonl · coder_b.jsonl
  4. 04

    逐字段比对

    Deterministic

    不调用模型。按字段比较 A 与 B，分为 agree / mismatch / missing_vs_value，并标出严重度。

    diff/cells.csv
  5. 05

    第三方裁决

    Only on diff

    只对分歧调用第三个模型：给建议值、原文证据、页码与理由。一致样本不重复花 token。

    adjudication.jsonl
  6. 06

    修改建议

    Human decides

    逐条采纳或驳回，写回 decisions 与 provenance。导出的每个文件带 sha256，改动有迹可循。

    revisions.md

G2 未开启时，真实调用被 403 拒绝，只允许 dry-run；G3 未开启时不能导出。门禁不是提示语，是服务端行为。

03 The interface

一条差异，
能点回到原文。

三屏界面由 HTML / CSS 直接绘制，不加载截图。点左侧切换；点带 ≠ 的差异行展开原文依据；修改意见可以当场采纳或驳回。所有数值均为构造样例。

已知边界

不假装解决
01

共享输入风险

A / B 读同一份 packet。摄取阶段的表格错位会被两个模型同时继承，分歧率会低估真实错误率。

02

模型版本漂移

厂商静默升级会让「同配置重跑」出现差异。以快照哈希与偏差登记处理，不做「再跑一次取平均」。

03

裁决者自身误差

裁决模型也是 LLM，它给出的 confidence 未校准。建议值仍需人核对原文。

04

规则解析非确定性

规则文档 → 字段表依赖模型，必须人工过一遍。无出处的字段直接丢弃，并记入 gaps。
